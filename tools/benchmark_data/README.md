# DDP Benchmark Data

Indexed by git commit. Each run records the firmware commit at time of measurement.

## Files

### compression_benchmark_\<commit\>.csv

60-row benchmark: 5 compression variants x 6 LED patterns x 2 pixel counts (800px, 3200px).
Generated by `tools/ddp_compression_benchmark.py` on host CPU (Python timing only, not ESP32).

Columns: `variant, pattern, pixels, mean_ratio, encode_us, decode_us, min_ratio, max_ratio`

### heap_transport_experiment_\<commit\>.csv

160-row repeated-measures experiment: 4 variants x 4 transports x 10 reps.
Generated by `tools/stat_experiment.py` on M5StickC at 30fps controlled rate, 10s runs.

Columns: `variant, transport, protocol, link, rep, eff_fps, heap_delta, heap_recovered, hg_fires, loop_lag, ratio, wire_kbps`

## Statistical Analysis

See `docs/ddp-readme.md` sec 18.6 for full analysis of the heap_transport_experiment data.

Key finding: transport explains 87% of variance in effective FPS (eta²=0.870, p<2e-16).
Codec variant explains 1% (eta²=0.010). Planar-RLE decode path has no statistically
detectable impact on loop lag, effective FPS, or heap usage vs byte-RLE (Wilcoxon p=0.54).
